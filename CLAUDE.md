# CLAUDE.md: unreal101

Guidance for AI assistants working in this repo.

## What this repo is

A **public** teaching repo: a 33-lesson path to learn C++ (lessons 01-18),
then C++ in Unreal Engine 5.8 (lessons 19-33), then a capstone (34). Audience: a high-school student
who knows basic JavaScript. Sibling repos in the same style:
`github.com/patdeg/ai101` and `github.com/patdeg/hello-docker`. Look at
`hello-docker` for the lesson-folder conventions before writing a lesson.

Note: Unity uses C#, not C++. Unreal Engine is the C++ engine. The repo name
`unreal101` reflects that. Do not write C# content here.

## Public-repo rules (hard)

- Nothing fleet-specific or private: no real hostnames, IPs, usernames,
  credentials, internal paths, or references to the author's other machines
  or projects (other than the two public sibling repos above).
- No secrets, tokens, or `.env` contents. Ever.
- `docs/` is gitignored on purpose. It holds planning documents, curriculum
  drafts, and session notes. Never commit it, never link to it from tracked
  files, and never copy its text into tracked files without cleaning it up.
- Do not commit or push unless asked.

Each lesson folder has a `README.md` plus source files. In Part 1, each lesson's
`main.cpp` is the whole Text Arena so far (a reference to compare against).
Part 2 lessons are written for UE 5.8 but have not been run on a real install;
the private list of open checks is `docs/part2-verify.md` (and `docs/part1-verify.md`
for MSVC items). Part 2 lessons that
need an Unreal project keep only the `Source/` code and config in git, never
generated folders (see `.gitignore`).

## Teaching principles

- **Start from JavaScript.** Introduce each C++ idea by contrast with the JS
  the student already knows ("In JS you write X; in C++ you must also say Y,
  and here is why").
- **One new idea at a time.** Every lesson has a goal, a small program, a
  "Try it", and a "Break it" exercise that causes a compiler error or bug on
  purpose and teaches how to read it.
- **Run it early.** The first program compiles in lesson 01. Never go more
  than a few minutes of reading without something to run.
- **Be honest about hard parts.** Pointers, memory, and undefined behavior are
  hard. Say so, and show the failure before the fix.
- **Modern C++ first.** Teach C++20 style: `std::string`, `std::vector`,
  range-for, `auto`, `std::unique_ptr`. Do not teach `malloc`, raw `new`/
  `delete`, or C arrays as the normal way. Mention them only to explain
  legacy code.
- **Unreal reality.** Part 2 uses Unreal's own types (`FString`, `TArray`,
  `UPROPERTY`, `UCLASS`) and its garbage collector. Always say how these
  relate to the standard-library idea taught in Part 1.
- **Every example must build.** Compile and run every code sample before
  committing it. Do not paste code that has not been built.

## Tooling

- Part 1: primary path is MSVC (`cl /std:c++20 /W4 /EHsc`) in the VS 2022
  Developer prompt on Windows. Keep code portable so `g++`/`clang++` with
  `-std=c++20 -Wall -Wextra` also builds it. CMake is undecided (see
  `docs/curriculum.md`).
- Part 2: Unreal Engine 5.8 on Windows (5.7 is the fallback). State the exact
  engine version a lesson was tested against in its README.
- Lessons are bite-size: 15-30 minutes of hands-on time, one idea each.

## Style for lesson text

- Short paragraphs, plain words, no hype. Write for a smart 15-year-old.
- Code blocks show the command and the expected output.
- Use ASCII hyphens and normal punctuation; avoid em dashes.

## Posters

The PDFs in `posters/` are generated by the private scripts in
`docs/poster/` (`build.py` renders HTML to PDF with headless Chromium;
`generate_images.py` made the mascot sprites). Only the PDFs are public. When
a lesson changes the syntax taught, update `build.py` and rebuild. Keep the
posters free of any private or fleet-specific content.
